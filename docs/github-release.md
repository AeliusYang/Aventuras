# GitHub 发布方式

源码分支与可下载程序均发布到维护者自己控制的 GitHub 仓库。

## 源码

把本源码副本提交到该仓库的开发或发布分支，保留上游许可证。发布时在经过验证的源码提交上创建版本标签，并用该标签创建 GitHub Release。标签应指向实际构建程序的提交；如果 fork 已有同名上游标签，使用能区分本发行版的标签，不移动已有标签。

GitHub 会为标签自动提供源码 ZIP 和 tar.gz。还可以附加经校验的源码包与 `SOURCE-MANIFEST.json`。

## Release 附件

建议提供 Windows 安装包、便携包、版本说明及 `SHA256SUMS.txt`。安装包和便携包作为 Release 附件上传，无须提交进 Git 分支。

附件必须从本发布源码重新构建。旧工作区的 EXE、安装包或便携包可能仍包含旧默认提示词，不能直接作为本版产物上传。便携包只包含程序所需文件，不打入应用数据库、API 配置、故事、角色卡或备份。

发布前应在隔离环境验证首次启动、API 配置、默认提示词绑定和故事创建，再根据验证状态选择正式发布或预发布。版本说明注明本版默认提示词、支持平台及已知限制。
